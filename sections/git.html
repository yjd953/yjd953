04 / Git learning and practice

Git 学习与实践.

从对象数据库和提交图出发，掌握日常操作、分支协作、历史排查、故障恢复与隐私安全。

基础模型

04 notes
01 Mental model / ZH / 三个区域 Git 到底在管理什么？ 从工作区、暂存区和本地仓库建立第一张地图，理解一次修改如何进入历史。 ↗ 02 Object model / ZH / Blob / Tree / Commit Git 的对象数据库里到底存了什么？ 拆解 Blob、Tree、Commit、Tag 与对象 ID，理解 Git 为什么更像快照数据库。 ↗ 03 Commit graph / ZH / 引用与可达性 分支和 HEAD 为什么只是指针？ 沿父提交关系建立提交图，解释 Branch、HEAD、Detached HEAD 与可达对象。 ↗ 04 Daily workflow / ZH / Status / Add / Commit 一次代码修改是怎样进入 Git 历史的？ 把 status、diff、add、commit 放进同一条数据流，学会精确控制每次提交。 ↗

历史与恢复

02 notes
05 History inspection / ZH / Log / Show / Blame Git 是怎样还原每次代码变化的？ 用 log、show、diff、blame 和文件历史追踪提交、代码行与变更来源。 ↗ 06 Undo and recovery / ZH / 按状态选择 写错以后，restore、reset、revert 应该选哪个？ 按未暂存、已暂存、已提交、已推送四种状态选择撤销方式，并用 Reflog 兜底。 ↗

分支与协作

04 notes
07 Branch and merge / ZH / 三方合并 分支、合并与冲突到底发生了什么？ 从共同祖先解释 Fast-forward、Merge Commit、三方合并与冲突解决。 ↗ 08 History editing / ZH / 复制提交 Rebase 和 Cherry-pick 为什么会改写提交？ 理解 Rebase 与 Cherry-pick 的本质是重新应用补丁，并掌握安全使用边界。 ↗ 09 Remotes / ZH / Fetch / Pull / Push 本地分支和远端分支究竟是什么关系？ 区分远端仓库、远端跟踪引用和本地分支，解释 fetch、pull、push 与 force-with-lease。 ↗ 10 Collaboration / ZH / Branch / PR / Review 一个可维护的 Git 协作流程应该怎样设计？ 从任务分支、提交粒度、Pull Request、Review 到合并策略设计团队工作流。 ↗

进阶工具

02 notes
11 Advanced tools / ZH / 临时状态与发布点 Stash、Worktree 和 Tag 分别解决什么问题？ 管理临时修改、并行工作目录和稳定发布标记，避免把不同任务混在一起。 ↗ 12 Debugging / ZH / 二分排查 怎样用 Git Bisect 定位引入 Bug 的提交？ 把好提交和坏提交交给 Git，通过二分搜索和自动化测试定位回归来源。 ↗

工程治理

03 notes
13 Repository hygiene / ZH / Ignore / Attributes / LFS 怎样保持一个 Git 仓库长期干净？ 处理忽略规则、换行、二进制文件、大文件、生成物和提交前检查。 ↗ 14 Identity and privacy / ZH / Author / Committer Git 提交身份、邮箱与签名是怎样工作的？ 区分 Author 与 Committer，理解邮箱暴露、仓库级身份、Noreply 邮箱和签名验证。 ↗ 15 History rewrite / ZH / Rewrite / Cleanup 怎样安全地改写历史并清除敏感信息？ 从对象可达性出发，处理错误邮箱、密钥、大文件和整仓历史重建，并验证清理结果。 ↗
