02.05 / Process / ZH

进程到底是什么？

从可执行文件到地址空间、文件描述符、栈、堆与 PID，解释程序为何不再只是文件。

磁盘上有一个文件：

/usr/local/bin/app

运行它以后，系统里出现 PID 1842。此时“程序”和“进程”已经不是同一件事。

程序是持久化的代码与数据描述；进程是操作系统为一次运行建立的动态上下文。它不仅包含机器指令，还包含地址空间、线程、文件描述符、权限、信号、调度与内核记账。

Program 是一份可执行描述

可执行文件通常保存：

  • 机器码；
  • 只读常量；
  • 已初始化全局数据；
  • 未初始化数据的大小；
  • 程序入口；
  • 动态库依赖；
  • 符号与重定位信息。

文件躺在磁盘上时不会消耗 CPU，也没有 PID。它可以被复制、校验 Hash、反汇编，但不会主动推进状态。

同一个文件可以启动多次：

./app &
./app &
./app &

得到三个进程。它们可以共享同一份只读代码页，却拥有不同的运行状态。

Process 是一次运行的身份

操作系统内核会为进程或任务维护控制结构。在 Linux 中，调度实体以 task_struct 等内核结构描述，并关联：

  • PID 与线程组；
  • 调度状态和优先级；
  • 虚拟内存描述；
  • 打开的文件；
  • 当前工作目录；
  • 用户与权限凭证；
  • 信号处理状态；
  • CPU 时间和资源限制；
  • 父子关系；
  • Namespace、Cgroup 等隔离信息。

进程不是内存中的某一块数据，而是这些资源和规则组合出来的抽象。

从文件到进程

典型路径：

可执行文件
→ Shell 创建子进程
→ execve 替换子进程映像
→ 内核建立地址空间与初始线程
→ Loader 映射代码和共享库
→ Runtime 初始化
→ main

execve 成功后，可执行文件本身仍在磁盘上。进程的代码页通常以文件映射方式关联它，访问时按需装入 Page Cache 和物理内存。

修改或删除路径，并不简单等于立刻抹掉正在运行的指令。Unix 文件语义允许已打开或已映射对象继续引用底层 Inode，直到最后一个引用释放。部署系统因此可以替换路径上的二进制，而旧进程继续运行旧映像。

Address Space：进程看到的内存世界

每个普通进程拥有自己的虚拟地址空间视图：

高地址
┌─────────────────────┐
│ Thread stacks       │
├─────────────────────┤
│ mmap regions        │  共享库、文件、匿名映射
├─────────────────────┤
│ Heap                │
├─────────────────────┤
│ BSS / Data          │
├─────────────────────┤
│ Text / Read-only    │
└─────────────────────┘
低地址

两个进程都可以访问虚拟地址 0x400000，却映射到不同物理页。页表由内核管理，CPU 的 MMU 完成地址转换。

这种隔离带来：

  • 一个进程通常不能随意读取另一个进程内存；
  • 每个进程可以拥有看似连续的地址；
  • 相同物理页可以映射进多个进程；
  • 页面可以尚未驻留、来自文件或被换出；
  • 权限可按页设置为读、写、执行。

地址空间是进程最核心的边界之一，但不是唯一边界。

Text、Data、Heap 和 Stack 的关系

Text

保存可执行机器码，通常只读且可执行。多个运行同一程序的进程可以共享相同物理代码页，因为它们不应修改代码。

Data 与 BSS

Data 对应已初始化全局变量，BSS 表示启动时应为零的区域。BSS 不必在可执行文件中存一大段零，只需记录大小。

每个进程通常拥有自己的可写副本。fork 后起初可通过 Copy-on-Write 共享，发生写入时再复制。

Heap

Heap 是动态分配器管理的进程地址空间区域。malloc 或 Go Runtime 从中或从独立 mmap 区域分配对象。

Heap 不等于所有空闲虚拟内存，也不等于已经占用的物理 RAM。

Stack

每个线程有自己的用户栈，保存：

  • 返回地址；
  • Spill 的局部值；
  • 部分函数参数；
  • 调用帧与临时空间。

所以说“进程有一个栈”只是单线程简化。多线程进程有共享地址空间，但每个线程需要独立栈和寄存器上下文。

File Descriptor：进程如何引用内核对象

用户程序调用：

int fd = open("data.txt", O_RDONLY);

返回的 fd 只是当前进程文件描述符表中的小整数索引：

Process FD Table
0 → stdin
1 → stdout
2 → stderr
3 → open file description → inode / socket / pipe

描述符 3 在另一个进程中可以指向完全不同对象。

fork 后父子进程的 FD Table 项通常引用同一 Open File Description，因此可能共享文件偏移。dup2 可以让两个描述符指向同一对象，Shell 用它实现管道与重定向。

“文件描述符”也不只对应磁盘文件，它还可以代表：

  • Socket；
  • Pipe；
  • Eventfd；
  • Epoll 实例；
  • 设备；
  • 匿名内存对象。

进程通过这些受内核管理的 Handle 与外部世界交互。

PID 是标识，不是进程本身

PID 是某个 PID Namespace 中的数字标识。它用于查找和管理任务，但：

  • 进程退出后 PID 可以被复用；
  • 容器内外看到的 PID 可能不同；
  • 多线程在 Linux 中有线程 ID 与线程组 ID 的区别；
  • PID 不承载进程状态，只是索引入口。

把长期业务身份只绑定 PID 会产生竞态。进程管理器通常还结合启动时间、Pidfd 或内部实例 ID，防止误操作后来复用同一 PID 的进程。

进程与线程如何组合

一个进程至少有一个线程。线程是被 Scheduler 实际调度的执行流。

同一进程中的线程通常共享：

  • 虚拟地址空间；
  • 代码和全局数据；
  • Heap；
  • 文件描述符表；
  • 当前工作目录；
  • 大部分权限状态。

每个线程独有：

  • 指令指针；
  • 通用寄存器；
  • Stack；
  • 调度状态；
  • 线程局部存储；
  • 部分信号状态。

所以进程更像资源与隔离容器，线程更像在其中推进指令的执行实体。

Process State 不只是“运行或停止”

从调度角度，一个任务可能处于：

Running / Runnable
Sleeping
Uninterruptible wait
Stopped
Zombie

Runnable 表示可以运行但正等待 CPU；Running 表示当前占用某个 Core；Sleeping 可能在等待网络、磁盘或定时器。

Zombie 并不是还在执行。它已经退出并释放大部分资源，只保留退出状态等少量信息，等待父进程通过 wait 回收。

这解释了为什么进程数量不等于同时占用 CPU 的数量。

一次系统调用如何跨越进程边界

用户进程执行：

read(fd, buffer, 4096);

它通过系统调用进入内核态。内核根据当前进程的 FD Table 找到对象，检查权限，执行文件或 Socket 读取。

如果数据尚未准备：

  1. 当前线程进入等待状态；
  2. Scheduler 选择其他线程运行；
  3. I/O 完成后设备中断或内核事件唤醒线程；
  4. 线程重新变为 Runnable；
  5. 某次调度后继续从系统调用返回处执行。

进程的连续体验，是内核保存和恢复执行上下文的结果，并不表示它一直占据 CPU。

fork 为什么能快速复制进程

朴素做法需要复制整个地址空间，成本很高。现代系统通常使用 Copy-on-Write：

fork 前：
Parent page table → Physical Page A

fork 后：
Parent page table ─┐
                   ├→ Physical Page A（只读/COW）
Child page table ──┘

Child 写入后：
Parent → Page A
Child  → copied Page B

页表和内核元数据仍有成本，但大部分物理页只在真正写入时复制。紧接着 execve 的子进程会抛弃旧地址空间，因此避免无意义的大量复制。

Process Isolation 不是绝对封闭

进程可以显式共享：

  • 共享内存；
  • Memory-mapped File；
  • Pipe 与 Socket；
  • 继承的文件描述符；
  • 信号；
  • ptrace 等调试接口。

权限和 Namespace 决定这些通道是否可用。容器也不是“另一台机器”，通常仍是宿主机内核中的进程，只是被 Namespace、Cgroup、Capabilities 和文件系统视图隔离。

为什么运行起来后不再只是那个文件

可以把差异列出来：

可执行文件 进程
磁盘上的字节 内核中的活动执行实体
没有 PID 有运行身份与生命周期
描述代码和静态数据 包含寄存器、线程和动态状态
不拥有地址空间 拥有虚拟地址空间
不持有打开的 Socket 拥有文件描述符表
不被 Scheduler 调度 线程被 Scheduler 调度
可被多次启动 每次启动形成独立实例

进程执行过程中还会不断偏离原始文件：

  • Heap 新增对象；
  • Stack 形成调用链；
  • 动态库被映射；
  • 配置与网络数据进入内存；
  • 文件描述符连接外部资源；
  • 寄存器保存当前计算状态；
  • 代码甚至可能通过 JIT 动态生成。

磁盘文件只提供启动映像的一部分。

用 /proc 观察一个真实进程

启动：

./app &
pid=$!

观察：

cat /proc/$pid/status
cat /proc/$pid/maps
ls -l /proc/$pid/fd
cat /proc/$pid/cmdline | tr '\0' ' '
cat /proc/$pid/environ | tr '\0' '\n'
ls /proc/$pid/task

这些入口分别展示：

  • 身份、状态和内存统计；
  • 虚拟内存映射；
  • 文件描述符；
  • 启动参数；
  • 环境变量；
  • 线程列表。

注意 /proc 受权限控制，命令行为也会因进程生命周期和 Linux 配置不同而变化。

进程是一组由内核维护的承诺

进程的本质不是“加载到内存里的程序”，而是操作系统提供的一组执行语义：

独立的虚拟地址视图
+ 一组可调度线程
+ 对内核对象的引用
+ 身份、权限和资源记账
+ 信号、生命周期与父子关系

可执行文件回答“有哪些代码和初始数据”；进程回答“这一次运行现在是谁、看到什么、执行到哪、拥有哪些资源”。

当程序真正运行起来后，文件只是它的来源之一。进程已经成为一个随时间变化、由内核持续维护的系统对象。
